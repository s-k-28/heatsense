## Shared visual hierarchy to implement

The repeated reference pattern is **utility context → major summary → one relevant daily status/action → contextual tools → current plan → compact metrics → dated history**, with exceptions moved above the summary when they block the task. Different viewports emphasize different parts of the same hierarchy; do not place every observed card on a single HeatSense screen.

For HeatSense, keep the field-condition orb as the defining hero and place three equal-size circles on one shared baseline underneath. The orb represents the **latest WBGT measurement and UIL zone**, not a personal health score. A circle’s label and unit must explain its value without relying on its arc colour. Neutral empty circles with “—” are appropriate when data is unavailable. A zero is appropriate only when the underlying count is known to be zero.

After the circles, one contextual block should explain the next relevant action. Use the existing design system’s canvas/surface, Barlow figure type, sentence-case text, ActionButton, Rows/ListRow and shared motion primitives. The source uses many uppercase labels, gradients, promotional illustrations and card grids; those do not need to transfer. Orb/circle styling follows the latest explicit user preference.

The scrolled references show a compact three-item summary above body sections. A compact summary is an optional later refinement, not evidence of specific WHOOP easing, thresholds or animation duration. First deliver a coherent static hierarchy that remains legible with reduced motion.

| First contextual block | First reading due, overdue recheck, or latest guidance to review | Current field action or genuine attention state with a Monitor destination | What today’s zone changes for practice; stop-and-tell-coach guidance when relevant |
| Secondary tools | Practice sheet, selected plan, roster/invite | Monitor, readiness/emergency plan, permitted WBGT logging | Band, read-only practice plan, athletic trainer |
| History | Today’s reading timeline, recorded practice-day history | Shared reading timeline and team practice history | Past team sessions and own available band detail |
| Missing access | Create team/sign in; no fabricated active practice | Join/approval state; coach must start practice | Join/pending approval state; do not expose inaccessible team data |

Circle choices above are recommendations, not claims of implementation. Prefer the same semantic quantities across roles where they apply; avoid three different unrelated “scores” merely to populate the layout. Staff-only actions must remain role-gated. A trainer’s need-attention count comes from existing flags; it is not a medical risk prediction.

### Circle denominator rules

- A recheck arc can encode elapsed fraction of the configured interval, while the centre shows minutes or overdue/now. The first reading is due immediately; there is no initial grace period.
- An acknowledgment arc can encode acknowledged readings divided by saved readings. With zero readings, show unavailable/empty and explain the first action.
- A reading-count circle should not imply a four-reading target unless the team actually configured that target. A count may use discrete ticks or a neutral outline without a completion percentage.
- A live-band count must distinguish active reporting athletes from roster size. A paired band is not necessarily live.
- A readiness arc may use checked items divided by the actual six-item readiness list; it must not claim medical clearance.
- An athlete acclimatization count must reflect recorded practice days and its known membership/history limits. Do not represent it as a validated readiness percentage.
