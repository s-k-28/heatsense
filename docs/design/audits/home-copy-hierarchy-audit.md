## Copy worth keeping

- **WBGT measured25 min ago** is useful, not disposable gray filler: it distinguishes an old observation from current weather (`coach-today.tsx:66`).
- **Simulated band readings** identifies what is not hardware data (`body-strip.tsx:27`). The header simulation chip covers device status; removing every local qualifier could confuse real field readings with simulated vitals.
- **3+ rest breaks each hour, at least4 minutes each** and cooling/equipment restrictions are concrete instructions (`role-tabs.tsx:50–52,80–82`). Do not delete them merely because their text is muted. Consider primary reading colour for the critical rule.
- **Feel off? Stop and tell a coach.** is a meaningful safety action, although the repeated symptom paragraph can be a deliberate expandable reminder rather than an obligatory footer after every visit (`role-tabs.tsx:118–123`).

## Empty/loading and seamlessness issues

1. **Loading and failure collapse into one view.** `useCoachData` returns null for both loading and errors (`src/state/team-session.ts:80–111`); shared Home interprets null as “Loading practice” indefinitely. A failed connection/permission state needs an honest retry or membership explanation. Extra skeletons or prose cannot fix the missing state distinction.
2. **Loading is described repeatedly.** Null data can show “Loading practice…” inside the orb, “Loading practice” above another “Loading your practice…” (`coach-today.tsx:46–47,62,91–93`). Use one loading treatment and avoid clickable empty metrics that only restate that no data exists.
3. **Practice days can appear known before history arrives.** `role-tabs.tsx:55–56` treats `past === null` as an empty list, temporarily producing a0/1 count. The hero then displays this as a real number. Unknown history should remain unknown until the records load.
4. **No team is not the same as no practice.** Coach's action is Start practice whenever session is absent (`coach-today.tsx:42`), but the sheet then asks an unconfigured coach to create a team. The action should match the prerequisite. The athlete's pending/declined/join states are already more explicit (`role-tabs.tsx:58–66`).
5. **Pull-to-refresh is only a timed spinner.** `src/app/dashboard.tsx:123–132` waits900ms and calls `markRefreshed`; it does not request a new observation or refresh the actual listeners. Home's measured timestamp is currently based on the real measurement, which is good; preserve that. Wire a genuine retry/reconnect where useful or remove the fake refresh acknowledgement. Do not imply a new WBGT measurement.
6. **Trainer Home navigates by pushing another dashboard.** `role-tabs.tsx:202–203` uses `router.push('/dashboard?role=trainer&tab=monitor')`, while the rest of dashboard navigation uses its local tab selection callback. This can create a second dashboard instance rather than a seamless tab change. Use the existing dashboard navigation context/callback when implementing the synthesis.
7. **History loading looks like empty history.** `coach-today.tsx:117` passes `past ?? []` into the calendar. It can briefly report no practice while records are loading. This is a state problem, not a need for another generic explanatory caption.

## Meaningful return use, rather than invented engagement

The current product already has reasons to return: the next real field check, staff guidance confirmation, a newly flagged band, and the saved record. Strengthen those loops rather than adding streaks, scores or prompts unsupported by the data.

- **Coach:** identify current practice → take/review the necessary reading → see the saved consequence → next due check remains visible.
- **Athlete:** see what today's field conditions require → inspect personal signals when needed → find staff/help and previous practices.
- **Trainer:** identify the person or field condition needing action → perform/record the check → return to a stable monitoring view.

These are retention hypotheses based on task utility, not measured retention effects. A CAC walkthrough can demonstrate them with an end-to-end change of state: a real reading changes guidance, a confirmation persists, ending practice creates an accessible record, and all three roles show the correct shared result. Useful review measures would be time to the correct next action, whether users understand the measurement's age/source, and whether they can retrieve the saved practice without explanation.

## Boundaries for the next pass

Keep the user-requested orb and three-circle visual identity. Edit copy and interaction only when it adds a concrete task, source, state or exception. Do not replace every caption with nothing; do not add an equivalent caption elsewhere. Before/after review should use the same team, reading, role, scroll position and viewport. No implementation was performed for this audit.
