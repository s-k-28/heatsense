## Remaining candidates and boundaries

1. **Shared membership lookup/error ambiguity:** `useMembership` stores unkeyed results and converts listener error to null. Noncoach Profile can therefore inherit stale account membership or mistake permission failure for no membership. Shared hook is outside this ownership; root should fix centrally and exercise account switching.
2. **Sign-out follow-up implemented:** Profile now guards repeated pending confirmation, awaits sign-out before navigation, shows a pending label, and presents a recoverable error if sign-out fails. Native cancellation, successful return and injected failure remain untested.
3. **Calendar month targets:** seven month columns cannot all achieve44 pt width inside a narrow padded card. Do not claim compliance from source. Consider a larger accessible date-selection alternative if runtime AX finds the grid difficult; avoid overlapping hit slop.
4. **Calendar cap provenance by caller:** AthleteSessions explains a full40-record window; coach Home passes a different cap. Calendar cannot imply complete monthly coverage. Root owns caller scope/disclosure decisions.
5. **History fetch errors:** `usePastSessions` maps listener failure to an empty list. This affects Profile and record discovery; an empty UI cannot establish zero practices. Shared-hook ownership belongs to root.
6. **Record direct-link fallback:** without back history, fallback currently selects athlete Sessions, even for coach/trainer record entry. Native stack return usually works; direct-link role behavior needs root product/route review.
7. **Long saved policy / venue / locale:** shared ListRow values and bar wrapping require native large-text/long-string screenshots. Source flex wrapping alone is not proof against clipping.
8. **Reference source limitations:** WHOOP/Strava evidence motivates hierarchy and record retrieval. Static references cannot establish animation durations, touch behavior or HeatSense usability; these remain app-specific verified contracts.
